08 / Server Authority

Server authority protects combat and inventory

Actions are validated transactionally on the server, preventing client-side manipulation of shared state.

Combat Validation

The server checks target identity, joined membership, valid range, and cooldowns before applying damage to the shared boss health.

Inventory & Crafting

Gathering validates resource proximity and identity. Crafting validates server-held material costs and enforces inventory limits.

Idempotency

Request receipts are stored within the transaction. This prevents duplicate damage or rewards if network retries occur.

Transactional Action Flow
1. BEGIN TRANSACTION
Lock room & member state
2. VALIDATE REQUEST
Check range, cost, cooldown
3. APPLY & RECEIPT
Mutate state, save request ID
4. COMMIT & RESPOND
Return authoritative result
